# 投机式解码

投机解码加速自动降低生成 (见 [autoregressive-generation.md](../04-generative-models/autoregressive-generation.md)) 通过重组*如何*词元生成,不改变其输出模型或统计分布.该文件涵盖了草案然后验证的框架,为什么它保留了准确的输出分布,以及两个显著的变体.

## 模型草案加上验证框架

**问题是核心的问题.**标准的自行退缩生成将每一个生成的词元每次打一个 (通常非常大,昂贵) 模型,严格序列地词元51不能生成直到词元50完成,每个调用都涉及到通过潜在巨大的模型的每个层进行完整的前进传递,尽管生成任何单个额外词元是,在信息理论意义上,通常是一个"便宜"的决定 (鉴于环境,许多词元是高度可预测的想完成"纽约"之后"我住在新").

**起源.**利维亚坦,卡尔曼,马蒂亚斯 (谷歌), "通过投机解码从Transformer中快速推理" (2023);陈等人 (DeepMind), "加速投机样本的大型语言模型解码" (2023) 两个独立的,紧密相关的论文,同时引入了相同的核心想法.

**核心机制.**用一个小,快的.**草案模型**快速生成一个短序列的几个候选词元连续这是快速的,正因为草案模型很小,每个单个前进通行都是便宜的.然后运行大型,昂贵的**目标模型**一次,在一个前进传递中,同时检查所有草案模型的候选词元 (因为Transformer可以在一个平行传递中分数整个已选定的词元序列,而不是每词元需要一个连续传递*培训*对于每个候选词元,对比大模型实际上将其自己的概率分配给该词元与草案模型的提案;接受词元,如果大模型同意足够密切,并拒绝 (并立即纠正) 意义重大分歧的第一点,抛弃该草案模型之后生成的任何候选词元.

```
   Prompt: "The capital of France is"

   1. DRAFT (small, fast model guesses 4 tokens ahead, cheaply):
         "Paris" → "," → "a" → "city"

   2. VERIFY (big model checks all 4 at once, in ONE parallel pass):
         "Paris"  ✓ agrees      → ACCEPT
         ","      ✓ agrees      → ACCEPT
         "a"      ✓ agrees      → ACCEPT
         "city"   ✗ disagrees   → REJECT here, big model supplies "the" instead

   3. RESULT of this one big-model step: "Paris , a the"  (3 draft tokens accepted + 1 correction)
      → 4 tokens produced for the price of ONE big-model pass, instead of four.
```

通过:而不是为每一个词元支付大模型的全部成本,你只支付大多数词元的 (更便宜) 草案模型的成本,并且每批候选人只支付大模型的成本,只支付一次并行验证通过,只要草案模型的猜测经常正确 (对于一个相当相对的草案模型在典型,相当可预测的文本上,它们经常是),这交易了许多昂贵的连续大模型调用一个昂贵的并行大型模型调用加上几次廉价的草案模型调用,大幅的净速度.最坏的情况也是安全的:如果模型是无用的,每个草案被拒绝,你会回到一个大模型词元的速度,比较快速的投机,在计算上永远不会浪费更多的词元.

## 为什么它加速生成,而不会改变输出分布

**关键的数学特性.**投机解码采用了特定的接受/拒绝规则 (一种拒绝样本采集形式,一种经典的统计样本采集技术),*终结*实际生成的词元序列的概率分布完全相同,就像如果单独的大型目标模型都以普通的方式生成了每个词元,一次一次.*提出*结果是大模型的判断最终决定了每个被接受的词元,并且任何词元大模型是否同意的词元都会被捕获并在验证过程中进行纠正.

**什么是这么重要? 农场通常不会得到"免费午餐".**在本节其他地方所述的大多数推理优化技术都以速度的某种程度进行了准确的交易 (量化见[quantization.md](quantization.md)和切割/蒸 见[pruning-and-distillation.md](pruning-and-distillation.md)两者都明确接受一些质量降低以换取效率).**输出的统计性质完全没有变化** FlashAttention对注意力计算本身提供相同的保证 (见 [kv-cache-and-attention-optimization.md](kv-cache-and-attention-optimization.md)),在此应用到整个生产过程中.

## 梅杜萨

**起源.**卡伊等人",Medusa:简单的LLM推理加速框架,具有多个解码头" (2024).

**核心贡献**梅杜萨不使用完全独立的草案模型,而是直接将几个额外的预测"头"添加到目标模型本身上,每个头都训练以预测一个词元在序列中更先 (一个头预测下一个词元,另一个预测前两个词元,等等),从而在一个通过中生成了单个目标模型的多个候选延续,然后通过类似的树木式接受方案进行验证.

**为什么这很重要.**梅杜萨避免训练,维护和保持单独的草案模型的运营复杂性,随着时间的推移与目标模型相匹配 (随着目标模型的更新或细节调整,单独的草案模型可以漂浮出与其一致的状态),通过直接将"草案"能力入目标模型本身.

## 头解码

**起源.**等",通过使用Lookahead解码来打破LLM推理的序列依赖性" (2024).

**核心贡献**通过利用生成过程的数学重组 (与可平行固定点代方法相关,与一些经典平行算法解决序列性看似问题相同的思想家族) 生成和验证候选续作,使用目标模型本身 (根本不需要单独的草案模型或额外训练的头脑),允许在几个前进传递中同时精炼多个未来词元猜测,并趋于模型会产生词元-按-词元的相同输出.

**为什么这很重要.**通过避免任何辅助模型或建筑变化,Lookahead解码可以直接与现有,未修改的目标模型使用的加快速度,每步换取一些额外的计算 (同时生成和精炼多个猜测) 以更少的总序列步骤.

## 实用加速数据 质量,没有过度要求

根据该库的质量条,本节故意避免将精确的加速度乘法列列列为普遍的事实,因为实际加速度大大取决于草案模型 (或Medusa的头部,或Lookahead解码的猜测) 如何匹配目标模型对生成的特定类型的实际行为. 具有高度可预测的文本 (结构化,模板化或低值输出) 看到比高度创造性的或不可预测的文本更大的加速度,其中模型的猜测较少被接受.可以说的是质量和信心:投机解码及其变体被广泛报告为提供有意义的,有时是实质性的,墙钟生成速度在典型的生产输出,没有影响到质量/分销. 这正是为什么这些技术在生产中需要采用,作为一个广泛的生产技术,作为一个分离式,分离式,分离式,分离式.
