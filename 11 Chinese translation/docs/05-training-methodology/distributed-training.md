# 分布式培训

训练一个边界规模模型需要同时将工作扩展到数百到数千个加速器 (GPU/TPU)  单个加速器,无论如何强大,既没有足够的内存来保持一个现代大型模型加上其训练状态,也没有足够的原始计算来训练它在合理的时间内.

答案是三个不同的"什么不适合/什么太慢"问题,*分裂*设备的不同情况:

```
 DATA PARALLELISM          TENSOR PARALLELISM         PIPELINE PARALLELISM
 (model fits; want          (one layer too big         (model too deep to fit;
  to go faster)              for one device)            split it by layers)

 GPU1: [whole model]        GPU1: [left half           GPU1: [layers 1-8]
       sees batch rows 1-4         of each layer]       GPU2: [layers 9-16]
 GPU2: [whole model]        GPU2: [right half          GPU3: [layers 17-24]
       sees batch rows 5-8         of each layer]       GPU4: [layers 25-32]
        │                          │                     data flows through
   average gradients          combine partial            like an assembly line:
   across GPUs                 results within             GPU1 → GPU2 → GPU3 → GPU4
   each step                   each layer

 splits: the DATA           splits: each WEIGHT        splits: the LAYERS
 (whole model copied)        MATRIX (needs fast          (needs less-frequent
                             within-node links)          cross-device handoffs)
```

在边界范围内,*合并*(通常称为3D平行性):将模型分成节点,将每个节点的层分成紧密连接的GPU,并将数据平行复制整个安排,以使用更多机器.ZERO/FSDP (下) 然后对四轴进行攻击.

## 数据平行性

**名称和定义**数据平行性复制了*整体*每个设备使用模型的相同副本处理不同批次的片段,并在每个参数更新之前,在所有设备中平均测量结果梯度.

**核心机制.**每个设备计算前进和后退的通行 (见 [optimization-algorithms.md](../01-foundations/optimization-algorithms.md)) 在自行分片的小批量,产生自己的地方梯度估计.**完全减少**操作 (一个集体通信模式,每个设备最终得到了所有设备的值的总和或平均值) 将这些本地梯度结合成一个平均梯度,然后每个设备都使用它来更新模型的自己的 (相同) 副本,在每个步骤后保持所有副本的同步.

**原因/限制**数据平行是最简单,最有效的通信平行战略 (只需要传达梯度,而不是激活或模型权重),并且在模型舒适地适应单个设备的内存时,可以很好地扩展训练吞吐量.其基本局限性是:它没有什么可减少保持模型本身,其激活和优化状态所需的内存.

## 模型/ensor平行性

**名称和定义**子平行化分开单个权重矩阵/层*在内*模型在多个设备上,因此没有一个设备需要保持整个层的全部权重.

**核心机制 (概念性).**对于一个大矩阵乘法 (整个Transformer中一个核心操作见[transformer-architecture.md](../03-deep-learning-architectures/transformer-architecture.md)),权重矩阵可以在几个设备中分开 (例如,通过列) ,每个设备使用其权重分片计算出自己的部分结果,部分结果被结合 (通过设备之间的通信) 来产生完整的正确输出.这需要设备在单层计算中多个点通信中间激活 (不仅是梯度,如数据平行性),这需要涉及的设备之间非常快速的互连 (这就是为什么平行性通常仅适用于)*在内*单个物理服务器/节点,设备通过非常高带宽链接连接而不是整个集群).

**为什么这很重要.**子平行直接解决数据平行的核心限制. 它允许一个模型太大,无法适应单个设备,被分为多个设备,而需要比数据平行通信更频繁,敏感的延迟设备之间的通信.

## 管道平行性

**名称和定义**管道平行化分裂了一个模型*按层次*,例如,模型的第一季度层在设备1上生活,下一个季度在设备2上,等等,数据在设备中流动,如一个组装线.

**核心机制.**由于每个设备只需要前台设备的层次输出 (而不是单层内细粒度的中间通信,不像光平行性),管道平行性需要更少频繁,更少的延迟敏感的通信. 对于分断模型的实际优势在不紧密互联的设备中 (例如,在集群中的不同节点/服务器中). 尽管这种天真版本有明显的效率低下:虽然设备1是空等待其输出通过设备2,3和4进行运行,并回来下一批,它没有做任何事情. "管道泡". 实际的管道平行性实现通过分断每一批小组减少了空时间.**微批量**通过管道供应它们,以重叠,分阶段的方式,以便设备1在微批次2上工作,设备2同时在微批次1上工作,使更多设备更忙,类似于CPU中的指示管道.

**为什么这很重要.**管道平行是子平行的自然补充:子平行处理在密切互连的设备组 (单个节点) 中的分离,而管道平行处理在不密切互连的组 (跨节点) 之间分离.大规模的训练运行通常结合了这两者,以及数据平行,在通常被称为**3D平行性**.

## 节点 1, 2, 3 阶段

**名称和定义**泽罗是一种消除标准数据平行性内存冗余的技术 (每个设备都保持优化器状态,梯度和参数的完整,相同副本) 的技术,通过将这些分断 (分开) 移动到数据平行设备中,同时保留数据平行性的相对简单的通信模式.

**起源.**拉斯利,拉布韦斯,他 (微软), "ZeRO:向训练万亿参数模型的记忆优化" (2020年).

**实际上每个阶段都会造成什么:**

- **罗第一阶段**碎了**优化器状态**(提醒从[optimization-algorithms.md](../01-foundations/optimization-algorithms.md)对于数据平行设备,这个状态通常是训练中最大的单个内存消费者,比参数或梯度本身更大.
- **罗第二阶段**另外还会碎**度**每个设备只需要保持与其拥有的优化状态碎片相关的梯度值,进一步减少内存.
- **罗第三阶段**另外还会碎**模型参数本身**没有单个设备可以保持模型的权重的完整副本; 相反,特定参数的细节,用于特定的计算,在使用前暂时从其他设备中收集,然后再释放.

步行:每个阶段都会进行更多的通信总费 (在实际需要计算时重建完整状态/梯度/参数) 实现每个设备所需的内存大幅减少.  最积极的阶段,允许您训练一个模型,其总规模 (在所有碎片中,结合在一起) 比任何单个设备的容量要大得多,使用普通的数据平行式训练逻辑下面,而不需要上述的更具侵入性的子/管道平行结构重组 (尽管ZRO经常在最大规模上与它们结合).

**为什么这很重要.**泽罗使得能够通过直接攻击内存问题的实际来源 (状态复制) 来训练非常大的模型,主要使用数据平行式基础设施 (比子/管线平行性更简单地推理和实现),而不是要求模型的计算本身进行重组.

## 完全碎片化数据并行 (FSDP)

**名称和定义**FSDP是 (具体而言,在PyTorch的生态系统中) 广泛应用的Zero 3阶段想法完整参数,梯度和优化状态碎片作为一个相对易于使用的训练包装而不是从零开始的定制实现.

**为什么这很重要.**根据FSDP的规定,在2026年,Zero-Stage-3型全面分断将成为更广泛的研究和工程界的广泛访问 (而不是需要定制的内部分布式培训基础设施),并与其他框架中的类似工具一起,成为2026年起用于大规模模型培训的最常用的工具之一.

## 通信瓶和硬件/互联网设计

**为什么这不仅仅是软件.**上面的每一个平行战略都具有通信成本 对数据平行的梯度平均,激活交换为子平行,以及激活对管道平行的交换 随着模型和集群的成长,这种通信已成为一级瓶,而不是后期思考.这就是为什么硬件和数据中心设计用于人工智能培训已经成为了自己的重要工程学科:在单个服务器内的加速器之间极高带宽,低延迟互联 (需要延迟敏感的频率通信),以及集群内的服务器之间高带宽网络 (需要数据平行平均和平行手机关节点) 鉴于原始的加速器如何有效地在网络上进行加速度,但人工智能实验室实际上可以确定为什么在网络上进行较差的互联网互联网的加速是非常有用的.

## 比较表

|战略|它们是什么?|沟通模式|典型范围|
|---|---|---|---|
|数据平行性|培训数据 (批量);模型完全复制|降低每一步的梯度|任何尺度,模型可以适合每设备|
|度平行性|单个权重矩阵/层|频繁,延迟敏感的激活交流|在一个密切互连的节点内|
|管道平行性|层组 (模型深度) |频率较低,阶段间的激活转移|在一个集群中跨节点|
|泽罗/FSDP |优化器状态 (第一阶段),+梯度 (2),+参数 (3) |根据需要,在数据并行通信上层次收集/释放碎片|任何规模;通常在最大规模的子/管道平行性结合|
