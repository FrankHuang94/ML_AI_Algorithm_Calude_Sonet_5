# Speculative Decoding

Speculative decoding speeds up autoregressive generation (see [autoregressive-generation.md](../04-generative-models/autoregressive-generation.md)) by restructuring *how* tokens are produced — without changing the model or the statistical distribution of its outputs at all. This file covers the draft-then-verify framing, why it preserves the exact output distribution, and two notable variants.

## The draft-model-plus-verification framing

**The core problem.** Standard autoregressive generation calls the (often very large, expensive) model once per generated token, strictly sequentially — token 51 can't be generated until token 50 is done, and each call involves a full forward pass through every layer of a potentially enormous model, even though generating any single additional token is, in an information-theoretic sense, often a "cheap" decision (many tokens are highly predictable given context — think of completing "New York" after "I live in New").

**Origin.** Leviathan, Kalman, Matias (Google), "Fast Inference from Transformers via Speculative Decoding" (2023); Chen et al. (DeepMind), "Accelerating Large Language Model Decoding with Speculative Sampling" (2023) — two independent, closely related papers introducing the same core idea around the same time.

**Core mechanism.** Use a small, fast **draft model** (a much smaller/cheaper model, ideally similar in behavior to the large target model) to quickly generate a short sequence of several candidate tokens in a row — this is fast precisely because the draft model is small and each of its individual forward passes is cheap. Then run the large, expensive **target model** once, in a single forward pass, to check all of the draft model's candidate tokens simultaneously (since a Transformer can score an entire sequence of already-chosen tokens in one parallel pass, rather than needing one sequential pass per token — the same parallelism that makes Transformer *training* efficient, applied here to verification instead of generation). For each candidate token, compare what the large model would have actually assigned as its own probability to that token against the draft model's proposal; accept tokens where the large model agrees closely enough, and reject (and immediately correct) the first point of meaningful disagreement, discarding any candidate tokens generated by the draft model after that point.

Walkthrough: instead of paying the full cost of the large model for every single token, you pay the (much cheaper) draft model's cost for most tokens and the large model's cost only once per batch of candidates, for a single parallel verification pass — as long as the draft model's guesses are frequently correct (which, for a reasonably well-matched draft model on typical, fairly predictable text, they often are), this trades many expensive sequential large-model calls for one expensive parallel large-model call plus several cheap draft-model calls, a substantial net speedup.

## Why it speeds up generation without changing the output distribution

**The key mathematical property.** Speculative decoding uses a specific acceptance/rejection rule (a form of rejection sampling, a classical statistical sampling technique) such that the *final* sequence of tokens actually produced has exactly the same probability distribution as if the large target model alone had generated every token, one at a time, in the ordinary way. The draft model only ever *proposes* candidates; it never gets to unilaterally decide what's actually output — the large model's judgment is what ultimately determines every accepted token, and any token the large model would have disagreed with sufficiently is caught and corrected during verification.

**Why this matters — a "free lunch" the field doesn't usually get.** Most inference-optimization techniques covered elsewhere in this section trade some amount of accuracy for speed (quantization — see [quantization.md](quantization.md) — and pruning/distillation — see [pruning-and-distillation.md](pruning-and-distillation.md) — both explicitly accept some quality degradation in exchange for efficiency). Speculative decoding is unusual in this repository's coverage precisely because it's a genuine speedup with **no change whatsoever to the statistical properties of the output** — the same guarantee FlashAttention offers for the attention computation itself (see [kv-cache-and-attention-optimization.md](kv-cache-and-attention-optimization.md)), applied here to the generation process as a whole.

## Medusa

**Origin.** Cai et al., "Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads" (2024).

**Core contribution.** Rather than using an entirely separate draft model, Medusa adds several extra prediction "heads" directly onto the target model itself, each trained to predict a token further ahead in the sequence (one head predicts the next token, another predicts two tokens ahead, and so on), generating multiple candidate continuations from the single target model in one pass, which are then verified using a similar tree-based acceptance scheme to standard speculative decoding.

**Why it mattered.** Medusa avoids the operational complexity of training, maintaining, and keeping a separate draft model well-matched to the target model over time (as the target model is updated or fine-tuned, a separate draft model can drift out of alignment with it) by baking the "drafting" capability directly into the target model itself.

## Lookahead decoding

**Origin.** Fu et al., "Break the Sequential Dependency of LLM Inference Using Lookahead Decoding" (2024).

**Core contribution.** Lookahead decoding generates and verifies candidate continuations using the target model itself (no separate draft model or extra trained heads needed at all), by exploiting a mathematical reformulation of the generation process (related to parallelizable fixed-point iteration methods, in the same broad family of ideas as some classical parallel algorithms for solving sequential-looking problems) that lets multiple future token guesses be refined in parallel across several forward passes, converging toward the same output the model would have produced token-by-token.

**Why it mattered.** By avoiding the need for any auxiliary model or architecture change, lookahead decoding offers speedups usable directly with an existing, unmodified target model, trading some additional compute per step (from generating and refining multiple guesses at once) for fewer total sequential steps.

## Practical speedup figures — qualitative, not overclaimed

Per this repository's quality bar, this section deliberately avoids stating precise speedup multipliers as universal facts, since actual speedup depends heavily on how well the draft model (or Medusa's heads, or lookahead decoding's guesses) matches the target model's actual behavior on the specific kind of text being generated — highly predictable text (structured, templated, or low-entropy output) sees larger speedups than highly creative or unpredictable text, where the draft model's guesses are accepted less often. What can be said qualitatively and with confidence: speculative decoding and its variants are widely reported to provide meaningful, sometimes substantial, wall-clock generation speedups in typical production workloads, with zero impact on output quality/distribution — which is precisely why these techniques have seen broad, rapid adoption across production LLM serving systems as of 2026, in contrast to techniques (quantization, pruning, distillation) that require an explicit quality-for-speed tradeoff decision.

## Comparison table

| Technique | Needs separate draft model? | Changes output distribution? | Key mechanism |
|---|---|---|---|
| Classic speculative decoding | Yes | No | Small draft model proposes, large model verifies in parallel |
| Medusa | No (extra heads on target model) | No | Multiple built-in prediction heads propose, tree-verified |
| Lookahead decoding | No | No | Parallel iterative refinement of multiple future-token guesses |

## Relationship to other algorithms

- Speculative decoding operates on top of, and is fully compatible with, the KV cache management techniques in [kv-cache-and-attention-optimization.md](kv-cache-and-attention-optimization.md).
- It is a complementary, stackable technique alongside quantization and pruning/distillation (see [quantization.md](quantization.md), [pruning-and-distillation.md](pruning-and-distillation.md)) — those change the model itself; speculative decoding changes only the generation *procedure*.
- Serving systems combine speculative decoding with the batching strategies in [serving-and-batching.md](serving-and-batching.md) to maximize overall throughput.
